=====================================================================
P4 PROMPTS - UI / UX polish (floating role)
Whoever finishes their own prompts first takes the next P4 prompt.
=====================================================================
Rules for P4 (read before claiming)
- Claim a prompt in the team chat first: "P4-2 claimed by P1". One person
  per P4 prompt at a time. Never run two P4 prompts in parallel.
- P4 owns ONLY frontend/src/styles/* and frontend/src/ui/* (after P3-1
  created them). Page files belong to P1/P2/P3 - P4-6 is the only prompt
  that touches pages, and only with the page owner's "OK" in chat.
- Never change component names, props, exports or CSS variable names
  (SPEC 16.4 and 16.5). Other people's pages depend on them. Adding a new
  OPTIONAL prop is allowed.
- Never change text claims, numbers or honesty badges. Styling only.
- Every P4 prompt ends with npm run build passing and a commit whose
  message starts "P4(<your P number>):".
- Best order: P4-1 -> P4-2 -> P4-3 -> P4-4 -> P4-5 -> P4-6.
  P4-1 and P4-2 give the biggest visual gain for the least time.
How to use: open Claude Code in chakra/, NEW session per prompt, copy
everything between the COPY lines.
If you use Google Antigravity (P3): new agent conversation in Planning
mode, and paste the "ANTIGRAVITY RULES" block from the top of any P3
prompt BEFORE the P4 prompt text.
---------------------------------------------------------------------

######################################################################
----- COPY BELOW -----
You are helping with the P4 (UI/UX) role on CHAKRA. First read SPEC.txt
in the repository root completely and follow every rule in Section 0.
Run git pull --rebase.

Files you may edit: frontend/src/styles/tokens.css,
frontend/src/styles/base.css. Nothing else.

Goal: one calm, professional visual system that matches the plan PDF
(deep green primary #1E6B47, clean white surfaces, the badge and owner
colours of SPEC 16.5). Keep every variable name of SPEC 16.5; you may add
new variables but not remove or rename any.
1. Read every file in frontend/src/ui and frontend/src/pages first so you
   know which variables are used. List any variable that is used but not
   defined, and define it.
2. tokens.css: refine values - an 8px spacing scale, radius 8px, a subtle
   shadow, a neutral grey scale for text/muted/border, font stacks
   (system UI sans; monospace for numbers is optional), and the risk
   colours (keep low = green, mid = amber, high = red; overflow darker
   red; review grey; reported purple).
3. Contrast: write a tiny Node script in a temp folder OUTSIDE the repo
   that computes the WCAG contrast ratio of: text on bg, text on surface,
   muted on surface, primary-contrast on primary, white on each badge
   colour, white on each owner colour. Print the table. Any pair below
   4.5:1 must be fixed by darkening the colour; print the table again.
   Delete the script afterwards.
4. base.css: typography scale (h1 28px, h2 20px, h3 16px, body 15px, line
   height 1.5), tabular numbers for .num, focus-visible outline using
   primary, link colours, page container, and no horizontal scroll at
   375px width. Respect prefers-reduced-motion.
5. npm run build (no errors). Commit only the two files:
   "P4(Px): design tokens and base styles", pull --rebase, push.
Report the final contrast table.
